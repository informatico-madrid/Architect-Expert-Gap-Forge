## Learnings
- DSPy (Pydantic) cannot have the same name as both InputField and OutputField in a class definition — Python class attributes can't be duplicated. Used `inferred_use_case` for the output field while keeping `use_case` for the input.
- epic.md lists incorrect output fields for TrajectorySignature (claims `tool_usage_patterns` — does not exist; actual type is `AgenticTrajectory` Pydantic model with `seed_id`, `mode`, `turns`, `errors`, `use_case`, `messages`)
- epic.md lists incorrect output fields for JudgeSignature (claims `coherence`/`overall` — does not exist; actual type is `NormalizedJudgeResponse` TypedDict with `baseline`, `adapter`, `reasoning`)
- CalibrationSignature must model optimization process (grid search → best params), NOT direct parameter-to-output mapping; `parameter_target` must be a structured Signature field, not embedded in system prompt text
- Hard query `_transform_to_abstract()` uses hardcoded Spanish if/else mapping — all Spanish strings should be replaced by DSPy ChainOfThought except the forbidden terms literal match strings
- `src/factory/prompt_builder.py` uses `string.Template.safe_substitute()` (dollars `$var`) while `trajectory_generator.py` uses `str.format()` (braces `{var}`) — both exist in codebase, DSPy Signatures should use `{var}` to match the trajectory generator convention
- `frontend_taxonomy_prompts.py` has 0 imports in `src/` directory (confirmed via grep) — safe to delete as dead code
- Backtracking detection logic exists in `src/curation/` (helpers, config) but the spec requires a new dedicated detector in `src/factory/` — the two are architecturally separate: one rewrites, the other analyzes trajectories
- DSPy 3.2.0 is confirmed pinned in `requirements.txt` AND installed in venv — API claims verified against source
- `dspy.ChainOfThought(MySignature)` prepends a `reasoning` field between inputs and outputs — needs wrapper when replacing HardQueryBuilder mapping since the return type must stay as a string
- "Architecture architecture" typo exists in prompts_judge.example.yaml line 10 (professor_exam section) — confirmed as bug #1 per design.md; must be replaced with "Architecture 2026" in docstrings
- Professor_judge section defines 5 scoring dimensions (ha_modernity, reasoning_depth, functionality, completeness, style) with detailed guidelines for nuance, identification vs implementation, and delta-focused scoring
