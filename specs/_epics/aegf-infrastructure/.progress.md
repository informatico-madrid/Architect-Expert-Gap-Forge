## Key Decomposition Decisions

1. **4 BMAD stories map to 4 specs directly** -- no merging or splitting needed. Each provides independent user value.
2. **Spec 4 (dependency-compatibility) has no real dependencies** -- the BMAD says "depends on Spec 2" but that's weak. Dependency checks don't care about prompt structure. Listed as start-immediately.
3. **Spec 2 (prompt-externalization) is XS, not S** -- research confirms prompts are already in taxonomy YAMLs. The `.example.yaml` pattern is extraction, not rewrite. Code references are read-only during extraction.
4. **Spec 3 is L, not M** -- human verification of 100-200 samples is the real bottleneck, not code. The builder script itself is small; the data production is manual.
5. **`.infrastructure/` is greenfield** -- no existing patterns to follow except `scripts/benchmark/` structure.

## Interface Contracts That Emerged

1. **Baseline result JSON schema** unified across all 3 baseline scripts (type, timestamp, score, details).
2. **`.example.yaml` pattern** with `prompts.<key>.system` and `prompts.<key>.user` structure.
3. **Anchor dataset JSONL** with explicit input/output field mapping for 3 DSPy signatures (TrajectorySignature, JudgeSignature, CalibrationSignature).
4. **`infrastructure/` directory ownership** -- Spec 1 creates it first, Spec 3 and Spec 4 add to it.

## Risks Identified

1. **numpy bug is pre-existing** -- `scripts/benchmark/measure_performance.py` imports numpy but it's not in requirements.txt. Spec 4 must fix this.
2. **No baseline JSONs exist yet** -- `scripts/benchmark/baselines/` is empty. Spec 1 must first RUN benchmarks to create initial data.
3. **Anchor data requires external model** -- requires OpenAI/Gemini/vLLM API access. This is an infrastructure dependency not in code.
4. **Dependency explosion** -- dspy + langgraph + torch ~3GB. Version pinning critical.
5. **Spearman not implemented anywhere** -- must use scipy.stats.spearmanr (new dependency).

## Dependencies Between Specs

```
Spec 4 (deps) ──► Spec 1 (baselines, needs scipy/numpy)
Spec 2 (prompts) ──► Spec 3 (anchors, needs English prompts)
Spec 1 (baselines) ──► Spec 3 (anchors, needs baseline quality validation)
Spec 4 ──┐
Spec 2 ──┼─► Phase 1 (parallel, day 1-2)
         └─► Phase 2 ──► Phase 3
```

Critical path: Spec 4 -> Spec 1 -> Spec 3
Spec 2 is parallel to critical path but blocks Spec 3.
