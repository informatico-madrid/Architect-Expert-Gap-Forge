# Module Discovery Auto-Detection

## Goal

Create an intelligent `auto` module discovery strategy that automatically detects the repository type based on file patterns and selects the appropriate discovery strategy (manifest, directory, filesystem, typescript, yaml) for processing repositories.

## Problem Statement

The current `module_discovery_strategy: manifest` configuration assumes all repositories have the same structure (HA core style), which is false for:
- Repos with only YAML files (e.g., basnijholt/lovelace-ios-themes)
- Repos with only compiled JS (e.g., Clooos/Bubble-Card)
- Repos with non-standard structures (e.g., joBr99/nspanel-lovelace-ui with AppDaemon)

## Acceptance Criteria

- [x] Strategy automatically detects repository type by scanning for file patterns (.py, .ts/.tsx, .yaml, .json)
- [x] For Python repos: chooses between `directory` or `filesystem` strategy
- [x] For TypeScript repos: uses `typescript` strategy
- [x] For YAML repos: uses `yaml` strategy
- [x] For compiled JS repos: correctly identifies as "no source to bundle"
- [ ] Falls back gracefully when initial strategy finds no modules (needs implementation)
- [x] Configurable in homeassistant.yaml with `module_discovery_strategy: auto`

## Research Phase: COMPLETED

Research completed on 2026-04-01. Key findings documented in `research.md`:

1. **Current Analysis**: All 7 discovery strategies exist in codebase:
   - `manifest`: manifest.json + __init__.py (HA core style)
   - `init`: __init__.py only (legacy Python)
   - `directory`: directory structure with __init__.py (HA core fallback)
   - `filesystem`: .php files in any subdir (PHP repos)
   - `typescript`: .ts/.tsx files in any subdir (Frontend TS)
   - `yaml`: .yaml/.yml/.jinja files in any subdir (Templates/Themes)
   - `manual_mapping`: explicit override configuration

2. **Problem Identified**: `module_discovery_strategy: manifest` fails for:
   - YAML-only repos (themes) - need `yaml` strategy
   - TypeScript-only repos (frontend) - need `typescript` strategy
   - PHP repos - need `filesystem` strategy
   - AppDaemon repos (non-standard Python) - need `directory` or `init` strategy

3. **Solution Design**: Implement `_detect_strategy()` function that:
   - Scans repository for file extension presence
   - Detects in priority order: YAML > TypeScript > PHP > manifest > directory
   - Returns most appropriate strategy name
   - Integrates seamlessly with existing discovery pipeline

4. **Implementation Plan**: 3 phases
   - Phase 1: Core implementation (add `_detect_strategy()`, update routing, config)
   - Phase 2: Testing (create test cases for each repo type)
   - Phase 3: Documentation (config docs, user guide)

5. **Code Examples**: Research includes 4 detailed examples showing detection for:
   - YAML-only theme repository (4 modules)
   - TypeScript frontend repository (2 modules)
   - PHP repository (3 modules)
   - Mixed Python + TypeScript repository (1 module)
