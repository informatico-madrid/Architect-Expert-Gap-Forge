## Learnings
- DSPy does NOT use a formal "anchor dataset" concept -- the term maps to three things: labeled demos (pre-provided input-output pairs), bootstrapped demos (auto-generated traces), and the training set (list of dspy.Example objects)
- Training data format is Python-native (`dspy.Example`), NOT JSONL
- `.with_inputs()` is mandatory -- it distinguishes input fields from label/ground-truth fields
- Ground truth in DSPy = label fields in Examples, evaluated by the metric function
- Recommended training set sizes: ~10 basic, ~50 broader search, ~200+ for extended optimization
- MIPROv2 is explicitly "data-aware and demonstration-aware" -- data quality directly drives instruction quality
- The three-phase process (bootstrapping -> grounded proposal -> discrete search) chains quality: bad data -> bad bootstrap traces -> bad instructions -> bad optimization
- `max_labeled_demos` + `max_bootstrapped_demos` share a combined budget in the final prompt

## New Learnings (2026-04-27)
- DSPy 3.2.0 `InputField`/`OutputField` are thin wrappers around `pydantic.Field` with `__dspy_field_type` metadata
- Typed outputs (`int`, `float`, `list[str]`, `Optional[str]`, `dict[str, str]`) are supported natively via Pydantic field annotations
- `ChainOfThought` is NOT a decorator -- it's a `Module` class that prepends a `reasoning` field to the signature
- MIPROv2 `compile()` returns a new program with optimized instructions + demos embedded on its predictors (not on signatures)
- `requires_permission_to_run` is REMOVED in 3.2.0; passing `True` raises ValueError
- `new_signature` kwarg is REMOVED from Predict; `assert` raises if used
- LM config requires `dspy.LM("provider/model")` not plain string in `dspy.configure()`
- DSPy has NO built-in `.example.yaml` loader; demos must be loaded manually as `dspy.Example(**row).with_inputs(...)`
- The existing `jsonl_to_dspy_examples` in the project does NOT call `.with_inputs()`, so it cannot distinguish inputs from labels
- `with_instructions()` returns a NEW Signature class; it does NOT mutate the original
- `AUTO_RUN_SETTINGS`: light={n:20, val:50}, medium={n:50, val:100}, heavy={n:100, val:200}
