### Calibration Quality Baseline Research (2026-04-25)
- **LDI is NOT a calibration metric**: It is a curation pipeline filter (`src/curation/quality_filter.py`) and factory pipeline gate (`src/factory/ldi_validator.py`). Measures code-to-reasoning length ratio. NOT present in calibration results.
- **Two LDI implementations exist**: Factory version (`code_len / reasoning_len`) and curation version (`code_tokens / (natural_tokens + code_tokens) * (code_tokens / (code_tokens + K))`). Both use K=1200.
- **Coherence IS a calibration metric**: Judge-dimension score (0-1) from LLM judge, weighted at 15% in calibration scoring (`CALIBRATION_SCORING_WEIGHTS`). Each CalibrationResult has `judge_scores.coherence`.
- **Grid size**: 6 params x 6 top_k x 5 min_p x 5 rep_penalty x 5 presence_penalty = 2,250 profiles. With 6 prompts = 13,500 iterations (before noxious filter pruning).
- **Grid search pivot values**: temperature=0.6, top_k=20, min_p=0.0, repetition_penalty=1.0, presence_penalty=1.0
- **Noxious filter**: Pre-filter evaluates each parameter value individually before full grid search; dynamic filter updates mid-run after each prompt sweep. Can reduce iterations dramatically.
- **Baseline script must combine two data sources**: Calibration results (for coherence) AND curation pipeline outputs or SampleRecord fields (for LDI).
- **Duration should be captured in baseline**: Supports AC #4 (MIPROv2 compile baseline comparison).
- **`infrastructure/baselines/` must be created** — directory does not exist. Must include `__init__.py` (listed in pyproject.toml coverage source).
